# iClaim - Dataset Guide

The project uses a **vehicle damage image dataset from Kaggle**. The raw data is never
committed to Git (see `.gitignore`).

> Keep the dataset, model checkpoints and Kaggle credentials out of public uploads. See
> `SECURITY.md` for the release checklist.

## 1. Choose a dataset

Search Kaggle for "car damage" / "vehicle damage" image datasets and pick one that:

- has **damage-type labels** (scratch, dent, crack, broken glass, ...);
- has a licence that allows academic use;
- has enough images per class (aim for 300+ per class if possible).

> fewer classes, edit `data.class_names` in `config.yaml` **and** the matching keys in
> `severity.class_prior` and `analytics.cost_ranges_inr`.

## 2. Download

Option A - Kaggle API (needs `~/.kaggle/kaggle.json`; never commit it):

```bash
pip install kaggle
kaggle datasets download -d <owner>/<dataset-slug> -p data/raw --unzip
```

Option B - download the zip in the browser and extract it into `data/raw/`.

## 3. Arrange folders

The loader expects one folder per class:

```
data/raw/
├── scratch/
├── dent/
├── crack/
├── broken_glass/
└── major_body_damage/
```

If your dataset uses different folder names, map them in `config.yaml`:

```yaml
data:
  folder_aliases:
    "Scratches": "scratch"
    "Dents": "dent"
    "Broken Glass": "broken_glass"
```

If the dataset ships as images + annotation files (COCO / YOLO / CSV), convert it to
class folders first. A "damaged vs. undamaged" dataset is **not** enough on its own, since
this project needs damage *types*.

## 4. Audit

```bash
python -m src.data_loader --audit
```

Check the printout for:

- class imbalance (ratio above 2:1 -> keep `training.use_class_weights: true`);
- duplicates (they are removed automatically when splitting, to prevent leakage);
- unreadable files;
- unusual image sizes.

The Streamlit uploader also rejects files above 10 MB and decoded images above 25 million
pixels. These limits protect the demo application; they do not replace dataset provenance,
licence or privacy review.

Also open the `notebooks/01_data_exploration.ipynb` notebook and look at sample images per
class. Spot-check for **label noise** (for example, a dent labelled as a scratch).

## 5. Split

```bash
python -m src.data_loader --prepare
```

Creates `data/processed/{train,val,test}/<class>/` using a stratified 70/15/15 split with a
fixed seed and writes `data/processed/split_manifest.csv`. The test set must stay untouched
until final evaluation.

## 6. Severity labels

Most datasets have **no severity labels**. The project therefore uses a rule-based severity
estimate (class prior + Grad-CAM damage area + confidence); see `src/severity.py`.
State this as an assumption in your report. If your dataset does include severity labels,
train a severity head instead and replace `src/severity.py`.

## 7. Claim data

Public vehicle-damage datasets rarely include claim records. The project ships a
**synthetic** `data/claims/claims_sample.csv` (generated by `python -m src.analytics --generate`).
Every row has `data_source = synthetic`, and the dashboard says so. Never present synthetic
claims or the indicative cost ranges in `config.yaml` as real insurer data.

## Dataset used in this run (observed)
Raw images were consolidated into data/raw/<class>/ and split with python -m src.data_loader --prepare:
- Classes: scratch, dent, crack, broken_glass, major_body_damage
- Total images: 5,095 (scratch 1,879; dent 1,663; broken_glass 948; major_body_damage 468; crack 137)
- Imbalance ratio: 13.7:1 -> training.use_class_weights: true (already set)
- Splits: train 3,567 / val 764 / test 764 (stratified 70/15/15, seed 42); manifest at data/processed/split_manifest.csv
- No duplicates or unreadable files found by --audit.
